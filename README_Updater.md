# ShadowTranslate: автообновление при запуске игры

## Как это работает
1. Плагин при загрузке (в `PluginLoader.LoadWithConfig`, до своей инициализации) запускает **отдельный процесс** `ShadowTranslate\ShadowTranslate.Updater.exe`. Сам exe вшит в `XUnity.AutoTranslator.Plugin.Core.dll` и распаковывается при старте, поэтому всегда той же версии, что и плагин, и в релизный zip его класть не нужно.
2. Обновлятор узнаёт последний тег релиза. Если версия актуальна или связи нет, игра запускается как обычно (ожидание не дольше `CheckTimeoutSeconds`, по умолчанию 12 с).
3. Если есть новая версия, **игра простаивает** (плагин ждёт статус), а обновлятор открывает **свою консоль** (не консоль BepInEx; она может быть выключена) и:
   - качает `ShadowTranslate.zip` **в оперативную память** (с докачкой, сменой источника, проверкой SHA-256);
   - проверяет архив: структура, CRC32 каждого файла, защита от `../`;
   - сравнивает файлы с диском по размеру и CRC32 и берёт только изменившиеся;
   - распаковывает их из памяти в `ShadowTranslate\stage` (игра ещё не тронута);
   - **закрывает игру**, под журналом заменяет файлы (старый уходит в backup, новый встаёт на его место) и при любой ошибке откатывает всё назад;
   - **перезапускает игру** с теми же аргументами. Перезапущенная игра один раз пропускает проверку, поэтому цикла не будет.
4. Весь ход пишется в `ShadowTranslate\updater.log`, даже если консоль скрыта. Плагин дублирует ключевые этапы в лог BepInEx строками `[ShadowUpdater]`.

Горячая подмена DLL без перезапуска невозможна (плагин уже загружен), поэтому реализован вариант «простой, лог, быстрый авто-перезапуск».

## Установка (4 шага)
1. Скопируйте в репозиторий с заменой/добавлением:
   - `XUnity.AutoTranslator.Plugin.Core.csproj` (замена: из него же собирается обновлятор и вшивается в DLL)
   - `XUnity.AutoTranslator.Plugin.Core/PluginLoader.cs` (замена: добавлен один вызов `ShadowUpdateGate.Run`)
   - `XUnity.AutoTranslator.Plugin.Core/Updating/ShadowUpdateGate.cs` (новый)
   - папку `Updater/` целиком (исходники обновлятора и тесты)
2. Соберите плагин как обычно: `dotnet build -c Release`. Одна команда собирает и обновлятор (net48), вшивает его в DLL, а в `bin\Release\` кладёт готовые `XUnity.AutoTranslator.Plugin.Core.dll` и `ShadowTranslate.Updater.exe`.
3. **Ставьте теги и версию так:** тег релиза = `<Version>` в csproj (`0.1.1` или `v0.1.1`). Файл релиза называйте `ShadowTranslate.zip`, структура как сейчас (корень архива = папка игры).
4. Выложите релиз. Первый релиз с этим модулем пользователи ставят вручную, дальше всё само.

Отдельной сборки обновлятора нет: при изменении его исходников `dotnet build -c Release` пересоберёт exe автоматически (результат промежуточной сборки лежит в `obj\updater`). Тесты под mono: `Updater/tests/run_tests.sh`.

## Что делается при сбоях
| Ситуация | Поведение |
|---|---|
| Нет интернета, DNS, блокировка | Проверка версии: 3 канала по очереди (редирект `/releases/latest`, GitHub API, `update.json` через raw и jsDelivr). Не ответили за 12 с: игра запускается как есть. Причина пишется в лог по-русски (DNS / сброс соединения / TLS / HTTP 451 / лимит API) |
| Лимит GitHub API (60/час на IP) | Основной канал редирект без лимитов, API только запасной |
| Блокировка github.com / CDN-хоста | Загрузка с зеркал из `Mirrors` (`ghfast.top`, `gh-proxy.com`, `ghproxy.net`). **Зеркалу доверия нет:** оно используется только если SHA-256 получен по TLS (страница релиза, API или `update.json`) и файл с ним совпал |
| Обрыв на середине | Докачка с места обрыва (Range), при отказе сервера докачивать начинает заново, дальше переход на следующий источник |
| Соединение «зависло» / очень медленное | Нет данных `StallSeconds` с: смена источника. Медленнее 30 КБ/с в первом круге: смена источника. Общий лимит 20 мин |
| Файл подменён или повреждён | Не сошёлся SHA-256, CRC32 или структура: данные отбрасываются, игра не тронута |
| Любая неудача обновления | Игра запускается на старой версии. Следующая попытка не раньше чем через 30, 60, 120 мин... (максимум 6 ч), чтобы не тормозить каждый запуск |
| Файл занят (антивирус, процесс не вышел) | Ожидание до 40 с, затем все изменения откатываются, игра запускается на старой версии |
| Обрыв во время замены (питание, kill) | Журнал `apply.journal`: при следующем запуске обновлятор закрывает игру, откатывает файлы, перезапускает игру |
| Нет места на диске | Проверка до начала замены, игра не тронута |
| Обновлятор завис или умер | Плагин по таймаутам продолжает запуск и убивает «брошенный» обновлятор |
| Пользователь не хочет ждать | Нажать **S** в консоли обновлятора: обновление пропущено |

## Что сохраняется, что заменяется
- По умолчанию заменяется **всё**, включая `BepInEx/config/*`: так можно заранее правильно настроить конфиг в релизе и обновлять его у всех. Чтобы оставить пользовательские файлы нетронутыми, впишите в `updater.ini` `Preserve=BepInEx/config/*` (шаблоны со `*`, несколько через `|`). Такие файлы не перезаписываются, если уже существуют.
- Переводы заменяются новыми, а старые копируются в `ShadowTranslate\backup-translations` (последние 3 версии), если пользователь правил их руками.
- Удаляются только файлы, которые обновлятор сам устанавливал в прошлый раз (манифест `installed.manifest`) и которых нет в новом релизе. Файлы игры и чужие моды не трогаются никогда. **При первом обновлении манифеста ещё нет, поэтому удалений не будет**; манифест создаётся после него.
- Папка `ShadowTranslate/` внутри архива игнорируется (она принадлежит обновляторю).

## Настройки
`ShadowTranslate\updater.ini` создаётся при первом запуске, там всё с комментариями: `Enabled`, `Console=auto|always|never`, таймауты, `Proxy`, `Mirrors`, `Preserve`, `RelaunchGame`. Переменная окружения `SHADOWTRANSLATE_NO_UPDATE=1` отключает проверку целиком. Ручной запуск: двойной щелчок по `ShadowTranslate.Updater.exe` (проверит и обновит, не трогая запущенную игру).

Необязательно, для устойчивости к блокировкам: положите в корень репозитория (ветка `main`) `update.json` вида `{"version":"0.1.1","sha256":"<sha256 zip>","size":83000000}`. Он читается через raw.githubusercontent.com и jsDelivr. Вручную не обновляйте: sha256 считается командой `certutil -hashfile ShadowTranslate.zip SHA256`.

## Что проверено, а что нет
Проверено: обновлятор и ворота плагина собраны Mono и прогнаны на **39 автоматических проверках** (`Updater/tests/run_tests.sh`, мок-GitHub): штатное обновление, актуальная версия, нет связи, 503 и лимит API, блокировка 451, обрыв и докачка, подмена файла (и подмена на зеркале), зависание, 404, зеркала, корневая папка в архиве, `../evil.txt`, откат при сбое посреди замены, восстановление после аварии. Реальный релиз 0.1.0 (83 МБ, 283 файла) скачан и разобран: структура и sha256 на странице релиза совпали с фактическим.

**Не проверено (в песочнице нет Windows, .NET SDK и игры):**
- сборка плагина на net6 (`ShadowUpdateGate.cs` использует только стандартные API и компилируется mcs, но полной сборки с вашими libs не было; если `dotnet build` что-то скажет, пришлите вывод);
- Windows-специфика: создание консоли, отключение крестика и QuickEdit, русский текст в консоли, замена занятых файлов, завершение игры;
- поведение в самой игре: пока игра ждёт обновлятор, окно может на время показать «Не отвечает», это нормально.

Известные риски: антивирус может ругнуться на exe, который качает файлы и закрывает процессы (при необходимости внесите папку `ShadowTranslate` в исключения); при запуске через Steam перезапуск идёт напрямую через exe (как и рекомендует ваш README); зеркала сторонние и могут умереть или смениться, поэтому список правится в `updater.ini`.
